# MED5652 Statistical Labs

A [Quarto](https://quarto.org) ebook for the R lab MED5652 Introduction to Epidemiology and Statistics. It contains two preparatory chapters and five weekly chapters. The repo also holds the course's seminar slide decks, built in `seminars/` as a separate Quarto project (`revealjs`). The published site is at <https://fredho-42.github.io/MED5652-IES-stats/>, book and slides together.

## Getting set up after cloning or forking

This project uses [renv](https://rstudio.github.io/renv/) to pin package versions, recorded in `renv.lock`, so everyone building the book gets the same package behaviour. Setup is not optional; the book will not render correctly against arbitrary, unpinned package versions.

1. Clone the repo (or your fork), then open `ies_stats_ebook` as a project in RStudio, or start R with that folder as the working directory.
2. On startup, R sources `.Rprofile`, which runs `renv/activate.R`. The first time this happens in a fresh clone, renv notices the project library (`renv/library/`) doesn't exist yet and bootstraps itself: it installs its own package into that new library, either from a local cache if one is available or by downloading it. You'll see renv's own progress messages in the console while this happens; that's expected.
3. Once renv is bootstrapped, run:

   ```r
   renv::restore()
   ```

   This reads `renv.lock` and installs every package at the exact version recorded there, into the project's own private library. It will list what it's about to install and ask for confirmation first. This can take a while the first time, since it may need to compile some packages from source depending on your platform.
4. Once `renv::restore()` finishes, you have everything needed to render the book:

   ```
   quarto render                                # the whole book (HTML + PDF)
   quarto render chapters/07-descriptive.qmd    # a single chapter, while iterating
   quarto preview                               # live preview while writing
   quarto render seminars                       # the seminar slide decks, a separate project
   ```

   Rendering the PDF requires a TeX distribution (`quarto install tinytex` if you don't already have one).

### If something goes wrong

- **`renv::restore()` fails partway through:** re-run it. It's safe to run repeatedly and only installs what's still missing or mismatched.
- **A package fails to install from source and you're not sure why:** check you have the R version `renv.lock` expects (`R.version.string` in the console; compare against `renv.lock`'s top-level `"R"` entry) and, on Linux, that any system libraries the failing package needs are installed.
- **Nothing in the console looks like renv is doing anything on first open:** confirm `.Rprofile` exists at the project root and that you opened R with the project folder as the working directory, since renv only activates for the project it's inside.

### Do not hand-edit `renv/activate.R`

This file is generated by renv itself (via `renv::activate()`), not written by hand. If you ever need to change how renv bootstraps, do it by running the relevant `renv::` function and let it regenerate the file, instead of editing the bootstrap logic directly. A hand edit here that isn't a genuine renv upgrade is easy to get subtly wrong (silently swallowing a failed package install, for example) and easy to miss in review, since the file is long, generated, and rarely read closely.

## Repo layout

```
_quarto.yml    # book config
index.qmd      # Introduction
chapters/      # the seven numbered teaching chapters, plus the closing Summary and the Glossary appendix
R/             # shared figure and helper code, sourced by chapters
data/          # the two datasets used across the course
images/        # cover image and chapter screenshots
renv.lock      # exact pinned package versions (see Getting set up, above)
seminars/      # the seminar slide decks: a separate, nested Quarto project (own _quarto.yml,
               # own custom.scss), not part of the book build
```

## Building and publishing

```
quarto render                                          # render the whole book locally
quarto render seminars --output-dir ../_book/seminars   # render the decks into the same output tree
quarto publish gh-pages                                 # publish everything in _book/ to GitHub Pages
```

Publishing pushes to the `gh-pages` branch, which GitHub Pages serves directly. This has to be done manually, and the two render steps above have to run first if the decks have changed, since `quarto publish` on its own only re-renders the book.
